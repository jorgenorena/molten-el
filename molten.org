* The user's model

The primitive operation is =(molten-eval-region BEG END)=. A user, another mode,
or a package such as code-cells chooses the range. Molten does not infer cells,
parse notebooks, or interpret the language. This keeps ordinary source files
usable and makes cell selection an independent concern.

The workflow is: connect to an existing Jupyter Server, select or start a kernel,
select source, and evaluate. The current server/kernel selection is shared by
buffers. A remote server can be exposed through SSH port forwarding; it uses
exactly the same transport as a server on localhost. Code executes in the
server's environment, not relative to the local source file.

Small output appears after the source. Large text and tracebacks get a compact
indication and an ordinary full-output buffer. Images are preferred when Emacs
can render them; terminal displays retain saved image bytes and show a fallback.
No output is inserted into the source. Re-execution creates a new record while
replacing the displayed result for that live range.

| User action | Command | Effect on records |
|-------------+---------+-------------------|
| Connect to a server | =molten-connect= | Keeps credentials in memory |
| Start or choose a kernel | =molten-start-kernel=, =molten-select-kernel= | Opens channels for future runs |
| Execute a selection or line | =molten-eval-region=, =molten-eval-line= | Creates a new execution |
| Execute the current range again | =molten-reeval= | Preserves previous history |
| Read full output | =molten-show-output= | Opens a snapshot in a regular buffer |
| Hide the displayed result | =molten-clear-output= | Saves the hidden flag; keeps history |
| Browse past runs | =molten-output-history= | Includes hidden and orphaned records |
| Control the kernel | =molten-interrupt=, =molten-restart-kernel=, =molten-kill-kernel= | Preserves saved output |
| Toggle presentation | =molten-mode= | Enables restoration and overlay refresh |

Reopening a file restores records without connecting to a server. “Fresh” means
that the executed source still matches. “Stale” means that its range is known
but the source changed. “Orphaned” means that automatic attachment would be a
guess. None of these labels describes kernel variables or dependencies.

* Boundaries and deliberately omitted features

The client uses built-in Elisp HTTP and JSON facilities and the pure-Elisp
=websocket= package. It does not launch Python, use ZMQ, load native modules, or
require emacs-jupyter. Loading and offline restoration do not even require the
WebSocket package; it is required only when opening channels.

| Module | Responsibility | Depends on |
|--------+----------------+------------|
| =molten-core.el= | Records, anchors, update notification, JSON conventions | Built-in libraries |
| =molten-jupyter.el= | REST control and asynchronous channels messages | Core, url; websocket when connecting |
| =molten-store.el= | Durable metadata and payloads, offline restoration | Core, json |
| =molten-display.el= | Overlays, image selection, full-output buffers | Core, ansi-color, button |
| =molten.el= | Commands, mode lifecycle, subscription wiring | The four modules above |

The flow is: command → execution record → backend request → correlated record
update → storage and display subscribers. Keeping records independent of
overlays makes offline history possible. The backend boundary and update hook
also leave room for another transport or dependency provider later, without
implementing either in this MVP.

Widgets, HTML/JavaScript, Plotly, Vega, stdin, completion, inspection, notebook
editing, cell/Quarto parsing and DAG/IPyflow semantics are outside this program.
Only =text/plain=, =image/png= and =image/svg+xml= are retained from MIME bundles.

* Records and source identity

Records are the durable model. A live buffer and a persistent file anchor solve
different problems: markers follow editing in this Emacs process; source and
context allow relocation in a later process.

** Four records, two kinds of identity

A session owns connection state and a message-ID lookup table. Its token and
socket never belong in a persisted execution. An execution records one request;
its anchor captures what was run, and its outputs preserve arrival order.

Execution state (=queued=, =running=, =done=, =error=, =aborted= or
=disconnected=) is separate from source freshness. A successful old execution
can have stale source. The =slot-id= identifies the displayed range across
re-executions, whereas =id= identifies one run. History is buffer-local and
newest first; the update hook carries a record rather than an overlay.

#+begin_src emacs-lisp :tangle molten-core.el

;;; Code:

** Identifiers and exact source capture

IDs combine process/time/random input and are opaque identifiers, not secrets.
Source hashes use UTF-8 bytes consistently so restoration does not depend on
the buffer's file encoding. The anchor stores the full executed text, original
line range and up to 120 characters of context on each side. Widening prevents
an unrelated narrowing from changing that context.

#+begin_src emacs-lisp :tangle molten-core.el
(defun molten-id ()
  "Return a unique opaque identifier without external programs."
  (secure-hash 'sha256 (format "%s:%s:%s:%s" (current-time) (emacs-pid)
                               (random) (buffer-name))))
(defun molten-hash (source)
  "Return the SHA256 of UTF-8 SOURCE."
  (secure-hash 'sha256 (encode-coding-string source 'utf-8-unix)))
(defun molten-anchor-create (beg end)
  "Capture a persistent anchor for BEG through END in the current buffer."
  (save-restriction
    (widen)
    (let ((source (buffer-substring-no-properties beg end)))
      (make-molten-anchor
       :file (and buffer-file-name (expand-file-name buffer-file-name))
       :line (line-number-at-pos beg) :end-line (line-number-at-pos end)
       :source source :hash (molten-hash source)
       :before (buffer-substring-no-properties (max (point-min) (- beg 120)) beg)
       :after (buffer-substring-no-properties end (min (point-max) (+ end 120)))))))
#+end_src

** Conservative relocation

Search all occurrences, including overlapping ones. A unique exact match
normally gives a fresh range, even if it moved. A unique nonempty context on
both sides can instead identify a changed range. If that enclosing range grew
around the old text, it is stale: finding an old substring alone is insufficient.

Duplicate exact matches are orphaned even when one is near the old line number.
If there is no exact match, both contexts must be unique and ordered before a
stale range can be attached. Missing context at file boundaries and edits to the
context can therefore orphan otherwise recognizable output. This sacrifices
some automatic recovery to avoid displaying a result beside the wrong source.
The saved approximate line range is useful in history, never proof of identity.

#+begin_src emacs-lisp :tangle molten-core.el
(defun molten--occurrences (text)
  "Return all start positions of nonempty TEXT in the widened buffer."
  (when (and text (not (string-empty-p text)))
    (save-excursion
      (goto-char (point-min))
      (let (positions)
        (while (search-forward text nil t)
          (push (- (point) (length text)) positions)
          (goto-char (1+ (- (point) (length text)))))
        (nreverse positions)))))
(defun molten-anchor-locate (anchor)
  "Return (BEG END FRESHNESS) for ANCHOR, or nil if ambiguous.
Unique exact source wins unless enclosing context identifies an expanded
range.  Changed source requires unique nonempty context on both sides;
line numbers alone never justify attachment."
  (save-restriction
    (widen)
    (let* ((source (molten-anchor-source anchor))
           (matches (molten--occurrences source))
           (before (molten-anchor-before anchor))
           (left (molten--occurrences before))
           (right (molten--occurrences (molten-anchor-after anchor)))
           (beg (and (= (length left) 1) (+ (car left) (length before))))
           (end (and (= (length right) 1) (car right)))
           (context (and beg end (<= beg end))))
      (cond
       ((= (length matches) 1)
        (let ((exact-beg (car matches)) (exact-end (+ (car matches) (length source))))
          (if (and context (<= beg exact-beg) (<= exact-end end)
                   (or (/= beg exact-beg) (/= end exact-end)))
              (list beg end 'stale)
            (list exact-beg exact-end 'fresh))))
       ;; Duplicate exact matches are intentionally orphaned.
       ((and (null matches) context) (list beg end 'stale))))))
#+end_src

** Creating history while replacing a presentation slot

Reject empty selections. Find the newest record with the same current marker
bounds and reuse its slot ID, but always allocate a new execution ID. The start
marker stays before text inserted at its position; the end marker advances with
insertions at the end. This treats edits at either boundary as part of the live
range and lets re-evaluation use its current contents. The anchor's original
source and hash remain immutable snapshots of what was actually sent.

#+begin_src emacs-lisp :tangle molten-core.el
(defun molten-execution-create (session beg end)
  "Create an execution in SESSION for BEG through END, preserving history."
  (when (>= beg end) (user-error "Select a nonempty source region"))
  (let* ((previous (cl-find-if
                    (lambda (e) (and (markerp (molten-execution-start e))
                                     (equal (marker-position (molten-execution-start e)) beg)
                                     (equal (marker-position (molten-execution-end e)) end)))
                    molten-executions))
         (id (molten-id))
         (e (make-molten-execution
             :id id :buffer (current-buffer) :file buffer-file-name
             :start (copy-marker beg) :end (copy-marker end t)
             :anchor (molten-anchor-create beg end) :timestamp (float-time)
             :session-id (molten-session-id session)
             :kernel-id (molten-session-kernel-id session)
             :kernel-name (molten-session-kernel-name session)
             :slot-id (if previous (molten-execution-slot-id previous) id))))
    (push e molten-executions)
    (puthash id e (molten-session-executions session))
    e))
#+end_src

** Freshness, updates, and output ordering

Hash the live marked range to refresh freshness; no dependency analysis is
performed. Notify subscribers only after the record has been updated. An ordered
output list preserves interleaved stdout, stderr and display results, while the
stdout/stderr fields also provide convenient accumulated stream text. A dead
buffer does not prevent its record from being stored by a later backend update.

#+begin_src emacs-lisp :tangle molten-core.el
(defun molten-execution-refresh (e)
  "Recompute source-only freshness of live execution E."
  (let ((start (molten-execution-start e)) (end (molten-execution-end e)))
    (when (and (markerp start) (marker-buffer start) (marker-position end))
      (with-current-buffer (marker-buffer start)
        (save-restriction
          (widen)
          (setf (molten-execution-freshness e)
                (if (equal (molten-anchor-hash (molten-execution-anchor e))
                           (molten-hash (buffer-substring-no-properties start end)))
                    'fresh 'stale)))))))
(defun molten-execution-notify (e)
  "Publish an update to E."
  (molten-execution-refresh e)
  (run-hook-with-args 'molten-execution-updated-hook e))
(defun molten-execution-add-output (e output)
  "Append OUTPUT to E in arrival order."
  (setf (molten-execution-outputs e)
        (nconc (molten-execution-outputs e) (list output)))
  (when (eq (molten-output-kind output) 'stream)
    (if (equal (molten-output-name output) "stderr")
        (setf (molten-execution-stderr e)
              (concat (molten-execution-stderr e) (molten-output-text output)))
      (setf (molten-execution-stdout e)
            (concat (molten-execution-stdout e) (molten-output-text output))))))
#+end_src

** A single JSON convention

Use the built-in Elisp reader with string keys, alist objects and list arrays.
This avoids a native JSON dependency and keeps wire decoding and storage decoding
consistent. Nil represents both JSON null and false when reading; requests that
must transmit false explicitly use =:json-false= when encoding.

#+begin_src emacs-lisp :tangle molten-core.el
(defun molten-json-read (text)
  "Parse TEXT using only the built-in Elisp JSON reader."
  (let ((json-object-type 'alist) (json-array-type 'list)
        (json-key-type 'string) (json-false nil) (json-null nil))
    (json-read-from-string text)))
(defun molten-get (key object) "Get string KEY from JSON OBJECT." (cdr (assoc key object)))
(provide 'molten-core)
;;; molten-core.el ends here
#+end_src

* Jupyter Server transport

The protocol choices came from the original MVP review of the official
[[https://jupyter-server.readthedocs.io/en/latest/developers/rest-api.html][REST API]],
[[https://jupyter-server.readthedocs.io/en/latest/developers/websocket-protocols.html][WebSocket wire protocol]],
[[https://jupyter-client.readthedocs.io/en/stable/messaging.html][messaging specification]], and
[[https://jupyter-server.readthedocs.io/en/latest/operators/security.html][authentication documentation]].
The implementation below is the existing MVP; the literate conversion does not
change its protocol behavior.

** Load only what offline clients can provide

Declare WebSocket functions for byte compilation, but defer requiring the
library until connection time. REST controls have a configurable timeout;
execution itself does not block Emacs waiting for the kernel.

#+begin_src emacs-lisp :tangle molten-jupyter.el
;;; molten-jupyter.el --- Jupyter Server REST and channels -*- lexical-binding: t; -*-
;; Generated from molten.org; edit that file, then run the tangle command.
;; SPDX-License-Identifier: GPL-3.0-or-later
;;; Commentary:
;; No client-side Python or ZMQ.  websocket.el is needed only when connecting.
;;; Code:
(require 'molten-core)
(require 'url)
(require 'url-http)
(declare-function websocket-open "websocket" (url &rest args))
(declare-function websocket-close "websocket" (websocket))
(declare-function websocket-send-text "websocket" (websocket text))
(declare-function websocket-frame-opcode "websocket" (frame))
(declare-function websocket-frame-payload "websocket" (frame))
(defcustom molten-http-timeout 15 "Seconds to wait for REST operations."
  :type 'number :group 'molten)
#+end_src

** Keep authentication out of URLs and records

Accept only HTTP(S) base URLs with no user credentials, query or fragment.
Reject line breaks in the token. Append API paths to the base URL so deployments
under a path prefix work. Authentication uses an Authorization header; the
session's token stays in memory and is excluded by storage's field allowlist.

#+begin_src emacs-lisp :tangle molten-jupyter.el
(defun molten-jupyter-session (url token)
  "Create a session for server base URL and memory-only TOKEN."
  (let ((parsed (url-generic-parse-url url)))
    (unless (and (member (url-type parsed) '("http" "https"))
                 (url-host parsed) (not (url-user parsed))
                 (not (url-target parsed))
                 (not (string-match-p "[?\n\r]" url)))
      (user-error "Use an http(s) base URL without credentials, query or fragment"))
    (when (string-match-p "[\n\r]" token) (user-error "Invalid token"))
    (make-molten-session :id (molten-id) :url (string-remove-suffix "/" url) :token token)))
(defun molten-jupyter--headers (s)
  "Return authentication headers for S."
  (unless (string-empty-p (or (molten-session-token s) ""))
    `(("Authorization" . ,(concat "token " (molten-session-token s))))))
#+end_src

** Bounded REST calls and cleanup

Kernel lifecycle operations are short synchronous HTTP requests; their timeout
is independent of code execution duration. Disable redirects, accept only 2xx
responses and handle empty responses such as HTTP 204. Always kill the response
buffer, including when parsing or status validation fails. The caller receives
parsed JSON rather than an HTTP buffer.

#+begin_src emacs-lisp :tangle molten-jupyter.el
(defun molten-jupyter-rest (s method path &optional data)
  "Call METHOD on PATH for S with optional JSON DATA.
Control operations are bounded and synchronous; code execution is asynchronous."
  (let* ((url-request-method method)
         (url-request-extra-headers
          (append '(("Content-Type" . "application/json")) (molten-jupyter--headers s)))
         (url-request-data (and data (encode-coding-string (json-encode data) 'utf-8)))
         (url-max-redirections 0)
         (buffer (url-retrieve-synchronously (concat (molten-session-url s) path)
                                            t t molten-http-timeout)))
    (unless buffer (error "Jupyter REST connection failed or timed out"))
    (unwind-protect
        (with-current-buffer buffer
          (unless (and (boundp 'url-http-response-status)
                       (numberp url-http-response-status)
                       (<= 200 url-http-response-status) (< url-http-response-status 300))
            (error "Jupyter REST %s %s failed (HTTP %s)" method path
                   (if (boundp 'url-http-response-status) url-http-response-status "unknown")))
          (goto-char (point-min))
          (unless (re-search-forward "\r?\n\r?\n" nil t) (error "Malformed HTTP response"))
          (unless (= (point) (point-max))
            (molten-json-read (decode-coding-string
                               (buffer-substring-no-properties (point) (point-max)) 'utf-8))))
      (kill-buffer buffer))))
#+end_src

** Kernel addressing and interrupted connections

A kernel ID selects REST resources. Closing its WebSocket detaches the client
without shutting down the kernel. Unfinished executions become disconnected and
notify subscribers so partial outputs survive. Completed history is untouched.
There is no automatic retry: re-sending an arbitrary region could repeat side
effects. Users explicitly select a kernel to reconnect.

#+begin_src emacs-lisp :tangle molten-jupyter.el
(defun molten-jupyter-list-kernels (s)
  "Return existing kernel models for S."
  (molten-jupyter-rest s "GET" "/api/kernels"))
(defun molten-jupyter--path (s &optional suffix)
  "Return the current kernel path for S with SUFFIX."
  (unless (molten-session-kernel-id s) (user-error "Select or start a kernel first"))
  (concat "/api/kernels/" (url-hexify-string (molten-session-kernel-id s)) suffix))
(defun molten-jupyter-disconnected (s)
  "Mark S and unfinished executions disconnected, preserving partial output."
  (setf (molten-session-state s) 'disconnected)
  (maphash (lambda (_ e)
             (when (memq (molten-execution-state e) '(queued busy running))
               (setf (molten-execution-state e) 'disconnected)
               (molten-execution-notify e)))
           (molten-session-executions s)))
(defun molten-jupyter-close (s)
  "Close S's transport without shutting down its kernel."
  (let ((ws (molten-session-socket s)))
    (setf (molten-session-socket s) nil)
    (when ws (websocket-close ws)))
  (molten-jupyter-disconnected s))
#+end_src

** Default WebSocket frames

No optional WebSocket subprotocol is requested. JSON text frames decode directly.
The default protocol can also send a binary envelope: big-endian 32-bit offsets
locate its JSON message and optional binary buffers. Check the table bounds and
monotonic offsets before slicing and decoding the JSON. Auxiliary buffers are
ignored because the supported MIME representations arrive in the JSON bundle;
this is not an implementation of widget buffers or the optional v1 framing.

#+begin_src emacs-lisp :tangle molten-jupyter.el
(defun molten-jupyter--u32 (bytes pos)
  "Read a big-endian uint32 in BYTES at POS."
  (when (> (+ pos 4) (length bytes)) (error "Truncated Jupyter binary frame"))
  (let ((value 0))
    (dotimes (i 4) (setq value (+ (ash value 8) (aref bytes (+ pos i)))))
    value))
(defun molten-jupyter-decode (payload &optional binary)
  "Decode default-protocol PAYLOAD; BINARY uses the legacy offset table.
Auxiliary binary buffers are not interpreted by this MVP."
  (when binary
    (let* ((n (molten-jupyter--u32 payload 0))
           (start (molten-jupyter--u32 payload 4))
           (end (if (> n 1) (molten-jupyter--u32 payload 8) (length payload))))
      (unless (and (> n 0) (= start (* 4 (1+ n)))
                   (<= start end) (<= end (length payload)))
        (error "Invalid Jupyter binary offsets"))
      (let ((last start))
        (dotimes (i n)
          (let ((offset (molten-jupyter--u32 payload (* 4 (1+ i)))))
            (unless (<= last offset (length payload)) (error "Invalid Jupyter binary offset"))
            (setq last offset))))
      (setq payload (substring payload start end))))
  (molten-json-read (decode-coding-string payload 'utf-8)))
#+end_src

** Callbacks own asynchronous reception

Open one channels connection and supply lexical closures over its session.
The channels URL contains a client session ID, not the token. Opening sets the
session ready; incoming messages are decoded and dispatched only for the current
socket. Close/error callbacks similarly ignore obsolete sockets. A failed open
marks pending work disconnected. Callback errors report the callback type without
dumping a connection object containing authentication headers.

#+begin_src emacs-lisp :tangle molten-jupyter.el
(defun molten-jupyter-open (s)
  "Open the default channels WebSocket for S."
  (unless (require 'websocket nil t)
    (user-error "Install the pure-Elisp websocket package to connect"))
  (molten-jupyter-close s)
  (setf (molten-session-state s) 'connecting)
  (condition-case err
      (setf (molten-session-socket s)
            (websocket-open
             (concat (replace-regexp-in-string "\\`http" "ws" (molten-session-url s))
                     (molten-jupyter--path s "/channels")
                     "?session_id=" (molten-session-id s))
             :custom-header-alist (molten-jupyter--headers s)
             :on-open (lambda (_ws) (setf (molten-session-state s) 'ready)
                        (message "Molten kernel connected"))
             :on-message
             (lambda (ws frame)
               (when (eq ws (molten-session-socket s))
                 (molten-jupyter-dispatch
                  s (molten-jupyter-decode (websocket-frame-payload frame)
                                           (eq (websocket-frame-opcode frame) 'binary)))))
             :on-close (lambda (ws)
                         (when (eq ws (molten-session-socket s))
                           (molten-jupyter-disconnected s)))
             :on-error (lambda (ws type _err)
                         (when (eq ws (molten-session-socket s))
                           (molten-jupyter-disconnected s)
                           (message "Molten WebSocket error (%s); reconnect the kernel" type)))))
    (error (molten-jupyter-disconnected s) (signal (car err) (cdr err)))))
#+end_src

** Kernel lifecycle operations

Selecting a different kernel closes the old transport and clears its routing
table; old execution records remain in buffer history and on disk. Starting
creates a kernel and then uses that same selection path. Restart closes and
reopens channels after the REST restart; interrupt leaves the connection intact.
Shutdown deletes the remote kernel and clears its selected ID.

#+begin_src emacs-lisp :tangle molten-jupyter.el
(defun molten-jupyter-select (s model)
  "Connect S to kernel MODEL."
  (molten-jupyter-close s)
  (clrhash (molten-session-executions s))
  (setf (molten-session-kernel-id s) (molten-get "id" model)
        (molten-session-kernel-name s) (molten-get "name" model))
  (molten-jupyter-open s))
(defun molten-jupyter-start (s name)
  "Start kernel NAME for S and open its channels."
  (molten-jupyter-select s (molten-jupyter-rest s "POST" "/api/kernels" `(("name" . ,name)))))
(defun molten-jupyter-interrupt (s)
  "Interrupt S's kernel."
  (molten-jupyter-rest s "POST" (molten-jupyter--path s "/interrupt")))
(defun molten-jupyter-restart (s)
  "Restart S's kernel and reconnect."
  (molten-jupyter-rest s "POST" (molten-jupyter--path s "/restart"))
  (molten-jupyter-close s)
  (clrhash (molten-session-executions s))
  (molten-jupyter-open s))
(defun molten-jupyter-kill (s)
  "Shut down S's kernel."

** The asynchronous execute request

Use the execution ID as the message ID and register it before sending. The
request goes to the shell channel and sends the anchor's source snapshot.
History is enabled, silent execution is disabled, and stdin is explicitly disabled
because this frontend has no prompt/reply UI. Empty metadata and expressions must
encode as JSON objects, while buffers encode as an array. A failed send records
disconnection rather than pretending execution succeeded.

#+begin_src emacs-lisp :tangle molten-jupyter.el
(defun molten-jupyter-execute (s e)
  "Send asynchronous execute_request for E over S."
  (unless (eq (molten-session-state s) 'ready) (user-error "Kernel channels are not ready"))
  (puthash (molten-execution-id e) e (molten-session-executions s))
  (condition-case err
      (websocket-send-text
       (molten-session-socket s)
       (json-encode
        `(("header" . (("msg_id" . ,(molten-execution-id e))
                        ("username" . "molten") ("session" . ,(molten-session-id s))
                        ("date" . ,(format-time-string "%Y-%m-%dT%H:%M:%SZ" nil t))
                        ("msg_type" . "execute_request") ("version" . "5.3")))
          ("parent_header" . ,(make-hash-table)) ("metadata" . ,(make-hash-table))
          ("channel" . "shell") ("buffers" . [])
          ("content" . (("code" . ,(molten-anchor-source (molten-execution-anchor e)))
                         ("silent" . :json-false) ("store_history" . t)
                         ("user_expressions" . ,(make-hash-table))
                         ("allow_stdin" . :json-false) ("stop_on_error" . t))))))
    (error (setf (molten-execution-state e) 'disconnected)
           (molten-execution-notify e) (signal (car err) (cdr err)))))

** Normalize the three supported representations

Retain only plain text, PNG and SVG. Join list-valued textual representations
and decode PNG base64 once at the transport boundary. Core records consequently
hold PNG bytes, ready for Emacs images and content-addressed storage. Display
chooses a representation later; it need not know about wire base64.

#+begin_src emacs-lisp :tangle molten-jupyter.el
(defun molten-jupyter--mime (data)
  "Normalize supported DATA, decoding PNG to bytes."
  (let (result)
    (dolist (mime '("text/plain" "image/png" "image/svg+xml"))
      (let ((value (molten-get mime data)))
        (when value
          (when (listp value) (setq value (apply #'concat value)))
          (when (equal mime "image/png") (setq value (base64-decode-string value)))
          (push (cons mime value) result))))
    (nreverse result)))
#+end_src

** Parent-ID correlation and completion ordering

Route by =parent_header.msg_id=, not by the most recent request or current
buffer. Unrelated traffic is ignored. Check the channel as well as message type:
streams/results/errors/status are IOPub traffic; execute replies belong to shell.

A reply and an IOPub idle can arrive in either order. Retain both facts and finish
only when both are present; busy changes the execution to running. The reply's
status selects done/error/aborted. Error replies supply a traceback if IOPub did
not already provide one. Keep completed IDs in the routing table so late
background output can still update their records. Every recognized update
notifies storage and display, including output received after completion.

#+begin_src emacs-lisp :tangle molten-jupyter.el
(defun molten-jupyter-dispatch (s message)
  "Apply correlated MESSAGE to S's execution records."
  (let* ((id (molten-get "msg_id" (molten-get "parent_header" message)))
         (e (and id (gethash id (molten-session-executions s))))
         (kind (molten-get "msg_type" (molten-get "header" message)))
         (channel (molten-get "channel" message))
         (c (molten-get "content" message))
         changed)
    (when e
      (cond
       ((and (equal channel "iopub")
             (member kind '("status" "stream" "execute_result" "display_data" "error")))
        (setq changed t)
        (pcase kind
          ("status"
           (pcase (molten-get "execution_state" c)
             ("busy" (setf (molten-execution-state e) 'running))
             ("idle" (setf (molten-execution-idle e) t))))
          ("stream"
           (molten-execution-add-output e (make-molten-output
                                          :kind 'stream :name (molten-get "name" c)
                                          :text (molten-get "text" c))))
          ((or "execute_result" "display_data")
           (when (molten-get "execution_count" c)
             (setf (molten-execution-count e) (molten-get "execution_count" c)))
           (molten-execution-add-output
            e (make-molten-output :kind (intern kind) :data (molten-jupyter--mime (molten-get "data" c))
                                  :metadata (molten-get "metadata" c))))
          ("error"
           (setf (molten-execution-traceback e)
                 (mapconcat #'identity (molten-get "traceback" c) "\n"))
           (molten-execution-add-output e (make-molten-output
                                          :kind 'error :text (molten-execution-traceback e))))))
       ((and (equal channel "shell") (equal kind "execute_reply"))
        (setq changed t)
        (setf (molten-execution-reply e) (molten-get "status" c)
              (molten-execution-count e) (molten-get "execution_count" c))
        (when (and (molten-get "traceback" c) (not (molten-execution-traceback e)))
          (setf (molten-execution-traceback e)
                (mapconcat #'identity (molten-get "traceback" c) "\n")))))
      (when changed
        (when (and (molten-execution-reply e) (molten-execution-idle e))
          (setf (molten-execution-state e)
                (pcase (molten-execution-reply e) ("ok" 'done) ("aborted" 'aborted) (_ 'error))))
        ;; Keep the mapping to accept late background output after idle.
        (molten-execution-notify e)))))
(provide 'molten-jupyter)

* Durable output and offline restoration

Persistence is an execution-record store, not a notebook format. Source files
are never used to hold output. Atomic metadata replacement avoids partially
written JSON becoming the only copy of an execution.

** Atomic writes with private permissions

Create the temporary file in the destination directory, write literal bytes,
set private permissions, then rename it over the destination. Keeping the rename
on one filesystem provides atomic replacement. =unwind-protect= removes a leftover
temporary file on failure. Directories use 0700 and files use 0600.

#+begin_src emacs-lisp :tangle molten-store.el
(defun molten-store--write (path bytes)
  "Atomically write BYTES to PATH with private permissions."
  (let ((dir (file-name-directory path)) temp)
    (make-directory dir t)
    (set-file-modes dir #o700)
    (unwind-protect
        (progn
          (setq temp (make-temp-file (expand-file-name ".write-" dir)))
          (let ((coding-system-for-write 'no-conversion))
            (write-region bytes nil temp nil 'silent))
          (set-file-modes temp #o600)
          (rename-file temp path t)
          (setq temp nil))
      (when (and temp (file-exists-p temp)) (delete-file temp)))))
#+end_src

** Content-addressed payloads

Text is encoded as UTF-8; PNG is already binary. The SHA256 of these bytes is
the filename, and identical payloads reuse the same blob. A reference carries
both the digest and binary/text interpretation. On read, require a hexadecimal
SHA256 filename and verify its content before returning bytes or decoded text.

All output payloads, including streams and tracebacks, use blobs. This avoids a
size-threshold special case but can leave unreferenced intermediate blobs after
stream updates. Garbage collection and retention policies are not implemented.

#+begin_src emacs-lisp :tangle molten-store.el
(defun molten-store--blob (text &optional binary)
  "Store TEXT, optionally BINARY, and return a blob reference."
  (let* ((bytes (if binary text (encode-coding-string text 'utf-8-unix)))
         (hash (secure-hash 'sha256 bytes))
         (path (expand-file-name (concat "blobs/" hash) molten-state-directory)))
    (unless (file-exists-p path) (molten-store--write path bytes))
    `(("blob" . ,hash) ("binary" . ,(if binary t :json-false)))))
(defun molten-store--read-blob (ref)
  "Read and verify REF."
  (let ((hash (molten-get "blob" ref)))
    (unless (and (stringp hash) (string-match-p "\\`[0-9a-f]\\{64\\}\\'" hash))
      (error "Invalid Molten blob reference"))
    (with-temp-buffer
      (set-buffer-multibyte nil)
      (insert-file-contents-literally
       (expand-file-name (concat "blobs/" hash) molten-state-directory))
      (unless (equal hash (secure-hash 'sha256 (current-buffer)))
        (error "Corrupt Molten blob %s" hash))
      (if (molten-get "binary" ref) (buffer-string)
        (decode-coding-string (buffer-string) 'utf-8-unix)))))
#+end_src

** An explicit persistence schema

Serialize only allowlisted fields: execution identity, original source anchor,
state/count, kernel identifiers, slot identity, hidden flag and output references.
Never serialize the live session, token, WebSocket, buffer or markers. This is an
authentication boundary, not a scrubber for user data: source and printed secrets
are still part of the user's execution record. Write blobs before publishing
metadata that references them. Non-file buffers do not create durable records.

#+begin_src emacs-lisp :tangle molten-store.el
(defun molten-store--fields (prefix fields record)
  "Extract allowlisted FIELDS using PREFIX accessors from RECORD."
  (mapcar (lambda (field)
            (cons (symbol-name field)
                  (funcall (intern (concat prefix (symbol-name field))) record))) fields))
(defun molten-store-save (e)
  "Persist execution E without session objects, transport handles or credentials."
  (when (molten-execution-file e)
    (let* ((a (molten-execution-anchor e))
           (record
            (append
             `(("version" . 1)
               ("state" . ,(symbol-name (molten-execution-state e)))
               ("anchor" . ,(molten-store--fields
                              "molten-anchor-" '(file line end-line source hash before after) a))
               ("outputs" .
                ,(vconcat
                  (mapcar
                   (lambda (o)
                     `(("kind" . ,(symbol-name (molten-output-kind o)))
                       ("name" . ,(molten-output-name o))
                       ("metadata" . ,(molten-output-metadata o))
                       ("text" . ,(and (molten-output-text o)
                                        (molten-store--blob (molten-output-text o))))
                       ("data" . ,(mapcar
                                    (lambda (pair)
                                      (cons (car pair) (molten-store--blob
                                                        (cdr pair) (equal (car pair) "image/png"))))
                                    (molten-output-data o)))))
                   (molten-execution-outputs e))))
               ("traceback" . ,(and (molten-execution-traceback e)
                                     (molten-store--blob (molten-execution-traceback e)))))
             (molten-store--fields "molten-execution-"
                                  '(id file timestamp session-id kernel-id kernel-name count slot-id hidden) e))))
      (molten-store--write
       (expand-file-name (concat "records/" (molten-execution-id e) ".json")
                         molten-state-directory)
       (encode-coding-string (json-encode record) 'utf-8-unix)))))
#+end_src

** Rebuilding records after a process exits

Require schema version 1 and reconstruct ordinary records, never evaluating
stored Lisp. Replaying outputs through the core append operation rebuilds the
stdout/stderr accumulators. A persisted queued/running execution becomes
disconnected because this new Emacs process cannot establish its completion.
Kernel IDs are historical information and do not initiate a connection.

#+begin_src emacs-lisp :tangle molten-store.el
(defun molten-store--decode (r)
  "Decode stored record R into an execution."
  (unless (equal (molten-get "version" r) 1) (error "Unknown Molten storage version"))
  (let* ((a (molten-get "anchor" r))
         (e (make-molten-execution
             :id (molten-get "id" r) :file (molten-get "file" r)
             :timestamp (molten-get "timestamp" r)
             :session-id (molten-get "session-id" r)
             :kernel-id (molten-get "kernel-id" r) :kernel-name (molten-get "kernel-name" r)
             :slot-id (molten-get "slot-id" r) :hidden (molten-get "hidden" r)
             :state (intern (molten-get "state" r)) :count (molten-get "count" r)
             :traceback (and (molten-get "traceback" r)
                             (molten-store--read-blob (molten-get "traceback" r)))
             :anchor (make-molten-anchor
                      :file (molten-get "file" a) :line (molten-get "line" a)
                      :end-line (molten-get "end-line" a) :source (molten-get "source" a)
                      :hash (molten-get "hash" a) :before (molten-get "before" a)
                      :after (molten-get "after" a)))))
    (when (memq (molten-execution-state e) '(queued busy running))
      (setf (molten-execution-state e) 'disconnected))
    (dolist (o (molten-get "outputs" r))
      (molten-execution-add-output
       e (make-molten-output
          :kind (intern (molten-get "kind" o)) :name (molten-get "name" o)
          :metadata (molten-get "metadata" o)
          :text (and (molten-get "text" o) (molten-store--read-blob (molten-get "text" o)))
          :data (mapcar (lambda (pair) (cons (car pair) (molten-store--read-blob (cdr pair))))
                        (molten-get "data" o)))))
    e))
#+end_src

** Restoration is independent of the kernel

Read records for the current absolute filename and sort newest first. A corrupt
record produces a warning and does not prevent other records from loading.
Relocate each anchor in the current buffer. Confident matches get fresh markers;
unmatched records receive orphaned freshness and remain available in history.
This simple MVP scans the record directory on restore; it has no database index
or filesystem watcher.

#+begin_src emacs-lisp :tangle molten-store.el
(defun molten-store-load (file)
  "Load execution history for FILE, newest first; skip damaged records."
  (let ((dir (expand-file-name "records/" molten-state-directory)) records)
    (when (file-directory-p dir)
      (dolist (path (directory-files dir t "\\.json\\'"))
        (condition-case err
            (let ((r (with-temp-buffer (insert-file-contents path)
                                      (molten-json-read (buffer-string)))))
              (when (equal (molten-get "file" r) (expand-file-name file))
                (push (molten-store--decode r) records)))
          (error (display-warning 'molten (format "Cannot restore %s: %s" path
                                                   (error-message-string err)))))))
    (sort records (lambda (a b) (> (molten-execution-timestamp a)
                                   (molten-execution-timestamp b))))))
(defun molten-store-restore ()
  "Restore current file history and confidently located live anchors."
  (when buffer-file-name
    (setq molten-executions (molten-store-load buffer-file-name))
    (dolist (e molten-executions)
      (let ((location (molten-anchor-locate (molten-execution-anchor e))))
        (setf (molten-execution-buffer e) (current-buffer)
              (molten-execution-freshness e) (or (nth 2 location) 'orphaned))
        (when location
          (setf (molten-execution-start e) (copy-marker (nth 0 location))
                (molten-execution-end e) (copy-marker (nth 1 location) t)))))))
(provide 'molten-store)

** One overlay per latest source slot

Rebuild overlays from newest-first history, considering each slot once. Mark a
slot seen even when its newest record is hidden so clearing output cannot reveal
an older result accidentally. Orphaned records have no markers and get no overlay.

The overlay spans the live source range but adds only an =after-string=. Use
numeric marker positions in the current presentation buffer: the source markers
can belong to a base buffer while an indirect buffer shows the same text. Passing
those foreign markers directly to =make-overlay= would signal an error. Its
summary shows execution state, freshness and count. Large text or any traceback
gets a pointer to =molten-show-output= instead of filling the source window.
Rebuilding after changes favors a small implementation over incremental caching;
it can become costly with very large histories.

#+begin_src emacs-lisp :tangle molten-display.el

          (unless (equal (sort relative #'string<) (sort (copy-sequence molten-tangle-files) #'string<))
            (error "Tangle targets differ from molten-tangle-files: %S" relative))
          (if check
              (let (different)
                (dolist (file molten-tangle-files)
                  (let ((committed (expand-file-name file root)))
                    (unless (and (file-exists-p committed)
                                 (equal (molten-tangle--bytes file)
                                        (molten-tangle--bytes committed)))
                      (push file different))))
                (when different
                  (error "Generated files out of date: %s; run the tangle command"
                         (mapconcat #'identity (nreverse different) ", ")))
                (princ "Literate source and generated files agree.\n"))
            (princ (format "Generated %d files from molten.org.\n" (length outputs))))))
    (when temporary (delete-directory temporary t))))
;;; tangle.el ends here
#+end_src

** Offline test runner

Check literate/generated agreement before loading the package. The minimal-load
check is its own clean process; ERT unit tests follow. The four restart phases
share a fresh temporary directory that the shell removes on exit. =EMACS= can
select another Emacs executable. Invocation through =sh= avoids depending on an
executable bit that tangling may not preserve.

#+begin_src sh :tangle test/run-tests.sh
#!/bin/sh
# Generated from molten.org; edit that file, then run the tangle command.
set -eu
cd "$(dirname "$0")/.."
EMACS=${EMACS:-emacs}
"$EMACS" --batch -Q -l tools/tangle.el --check
"$EMACS" --batch -Q -L . -l test/load-minimal.el
"$EMACS" --batch -Q -L . -l test/molten-test.el -f ert-run-tests-batch-and-exit
MOLTEN_TEST_DIR=$(mktemp -d)
export MOLTEN_TEST_DIR
trap 'rm -rf "$MOLTEN_TEST_DIR"' EXIT HUP INT TERM
for phase in seed fresh stale orphan; do
    MOLTEN_TEST_PHASE="molten-process-$phase" "$EMACS" --batch -Q -L . -l test/restart.el
done
#+end_src

** Make targets

These are convenience wrappers around the documented Emacs and shell commands;
GNU Make is not required to develop the package. Compilation requires agreement
with the literate source and treats byte-compiler warnings as errors. Cleaning
removes only generated bytecode, not the checked-in tangled Elisp sources.

#+begin_src makefile :tangle Makefile
# Generated from molten.org; edit that file, then run the tangle command.
EMACS ?= emacs
.PHONY: tangle check-tangle test compile clean
tangle:
	$(EMACS) --batch -Q -l tools/tangle.el
check-tangle:
	$(EMACS) --batch -Q -l tools/tangle.el --check
test:
	EMACS=$(EMACS) sh test/run-tests.sh
compile: check-tangle
	$(EMACS) --batch -Q -L . --eval '(setq byte-compile-error-on-warn t)' -f batch-byte-compile molten-core.el molten-store.el molten-jupyter.el molten-display.el molten.el
clean:
	rm -f molten*.elc
#+end_src
